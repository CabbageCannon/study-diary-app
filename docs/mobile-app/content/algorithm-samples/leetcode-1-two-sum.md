## 题意摘要（原创，可独立阅读）

给定一个整数数组 `nums` 和一个整数目标值 `target`。请在数组中找出**两个不同位置**上的数，使它们的和恰好等于 `target`，并返回这两个位置的下标。

规则：

- 每个输入**保证恰好存在一组**有效答案。
- 同一个下标上的数不能使用两次（即使该值在数组别处再次出现，也必须用另一个位置）。
- 返回的两个下标先后顺序不限。

## 输入

- `nums`：整数数组，可能含负数、零和重复值。
- `target`：整数，可能为负数或零。

## 输出

- 一个包含两个下标的数组（或等价形式），表示所选的两个位置。

## 约束（本内容采用的规格，供核对使用；与原题的差异以原题链接为准）

- `2 ≤ nums.length ≤ 10^4`
- `-10^9 ≤ nums[i] ≤ 10^9`，`-10^9 ≤ target ≤ 10^9`
- 恰好存在一组答案；答案的两个下标必须不同。
- 数组不保证有序；重复值允许出现。

## 原创示例

示例 1：

```
输入: nums = [3, 2, 4], target = 6
输出: [1, 2]
解释: nums[1] + nums[2] = 2 + 4 = 6。注意不能返回 [0, 0]：
      虽然 3 + 3 = 6，但下标 0 上的 3 只有一个，不能重复使用同一位置。
```

示例 2：

```
输入: nums = [-3, 0, 3], target = 0
输出: [0, 2]
解释: -3 + 3 = 0。覆盖负数与零的组合。
```

示例 3：

```
输入: nums = [5, 5], target = 10
输出: [0, 1]
解释: 两个值相同但位置不同，这是合法的；答案必须用两个不同下标。
```

## 可接受方案（不止一种，不作为唯一正确答案）

1. **一次遍历哈希表（目标解法）**：边遍历边用哈希表记录“已见过的值 → 下标”。对当前值 `x`，**先**查表中是否已有补数 `target - x`，**再**把 `x` 存入表中。这样查到的补数一定来自更早的位置，天然避免同一位置使用两次。时间 O(n)，额外空间 O(n)。
2. **暴力双重循环**：枚举所有下标对 `(i, j)`，`i < j`，检查 `nums[i] + nums[j] == target`。时间 O(n²)，额外空间 O(1)。在给定约束（n ≤ 10^4）下可通过，是**正确但非最优**的方案；核对时应认可其正确性，并引导说出哈希优化。
3. **排序 + 二分/双指针找补数**：先把 `(值, 原下标)` 一起排序，再对每个值二分查找补数，或用双指针从两端夹逼。时间 O(n log n)，空间 O(n)（保存原下标）。正确但通常不比一次遍历哈希更好；关键是**必须保留原下标**，否则返回的是排序后位置。

## 核对要点（verification / reference points）

用户口述思路时，核对以这些点为依据；“必须覆盖”指缺少时结论不应是“思路成立”。

| # | 要点 | 级别 |
| --- | --- | --- |
| V1 | 明确返回的是**下标（位置）**而不是数值本身 | 必须覆盖 |
| V2 | 说明如何避免同一位置使用两次：如“先查补数、再存当前值”，或暴力法中 `i < j`，或其他等价机制 | 必须覆盖 |
| V3 | 复杂度表述与所选方案一致（哈希 O(n)/O(n)；暴力 O(n²)/O(1)；排序类 O(n log n)） | 必须覆盖（若用户主动谈复杂度，则要求正确） |
| V4 | 意识到数组可能含负数/零/重复值，方案不依赖“值均为正”或“数组有序” | 应覆盖 |
| V5 | 提到恰好一组答案，因此找到即可返回 | 加分项 |

注意：用户不需要说出“哈希表”这个词；只要能说明“用某种方式记住已经见过的数及其位置，从而快速找到补数”，即视为覆盖 V2 的哈希类思路。含糊表述（如“用个什么东西存一下”）应追问而不是直接判错。

## 常见错误

- **先存后查**：把当前值先放入哈希表再查补数；当 `target = 2 × x` 时补数会命中刚存入的自己，返回 `[i, i]`。
- **先建全表再查**：先把所有值建表再逐个查补数，未处理“补数下标等于当前下标”的情况，同样可能重复使用同一位置；重复值建表时后者覆盖前者，还可能漏掉正确配对。
- **返回值而非下标**，或返回排序后的位置而非原下标。
- **在未排序数组上直接用双指针**从两端夹逼——双指针依赖有序性。
- 误以为重复值（如 `[5, 5]`）不合法而跳过。

## 边界情况

- 数组恰好 2 个元素（最小规模）。
- 补数等于自身：`target` 为某值的两倍，且该值只出现一次（不可用）或出现两次（可用，取两个不同下标）。
- 负数与零混合；`target` 为负数或零。
- 重复值出现在答案中（示例 3）与出现在答案外两种情形。

## 有区分力的反例

反例 A（区分“先存后查”错误）：

```
nums = [3, 2, 4], target = 6
错误实现（先存当前值再查补数）: i=0 时存入 3，查 6-3=3 命中刚存的自己，返回 [0, 0]。
正确输出: [1, 2]
```

反例 B（区分“先建全表”中重复值覆盖问题）：

```
nums = [3, 2, 3], target = 6
若先建全表且同值后者覆盖前者，3 只映射到下标 2；
对 i=0 查补数得 [0, 2] 恰好正确，但对 i=2 再查会得到 [2, 2]（命中自己），
需要额外判断“补数下标 ≠ 当前下标”。一次遍历“先查后存”则无此问题。
```

## 复杂度要求

- 时间：目标 O(n)（一次遍历哈希）。O(n²) 暴力视为正确但应被指出可优化；O(n log n) 排序类可接受。
- 空间：哈希方案额外空间 O(n)；暴力 O(1)。声称哈希方案 O(1) 额外空间是错误的。
