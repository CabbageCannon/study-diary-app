## 题意摘要（原创，可独立阅读）

给定一个整数数组 `nums`，找出所有和为 0 的**三元组**，即三个**互不相同的下标** `(i, j, k)` 满足 `nums[i] + nums[j] + nums[k] = 0`，返回这些三元组组成的列表。

规则：

- 三个下标必须互不相同，但**不同下标上的相同值可以**同时出现在一个三元组里（例如数组中有两个 `-1` 时，`[-1, -1, 2]` 是合法三元组）。
- 返回列表中**不能包含重复的三元组**：两个三元组只要包含的数（按多重集合，即计重数）相同，就视为同一个，无论内部排列顺序如何。
- 三元组内部顺序、返回列表的顺序均不限。

## 输入

- `nums`：整数数组，可能无序、含重复值、含负数和零；长度可能小于 3。

## 输出

- 所有不重复的、和为 0 的三元组组成的列表；无解时返回空列表。

## 约束（本内容采用的规格，供核对使用；与原题的差异以原题链接为准）

- `0 ≤ nums.length ≤ 3000`
- `-10^5 ≤ nums[i] ≤ 10^5`
- 数组不保证有序；重复值允许出现。
- 长度小于 3 时答案必为空列表。

## 原创示例

示例 1：

```
输入: nums = [-2, -2, 0, 2, 2, 4]
输出: [[-2, -2, 4], [-2, 0, 2]]
解释: (-2) + (-2) + 4 = 0，两个 -2 来自不同下标，合法；
      (-2) + 0 + 2 = 0。数组里有两个 -2 和两个 2，
      但 [-2, 0, 2] 只能出现一次——值来源不同不产生新三元组。
```

示例 2：

```
输入: nums = [1, 2, 3]
输出: []
解释: 全为正数，任意三个数之和不可能为 0。
```

示例 3：

```
输入: nums = [0, 0, 0, 0]
输出: [[0, 0, 0]]
解释: 有 4 个 0，任选三个下标都成立，但 [0, 0, 0] 作为三元组只能输出一次。
```

## 可接受方案（不止一种，不作为唯一正确答案）

1. **排序 + 固定一个数 + 双指针（目标解法）**：先排序。从小到大固定下标 `i`（值 `a`），在 `i` 右侧区间用左右指针 `l`、`r` 夹逼找 `b + c = -a`：和偏大则 `r` 左移，偏小则 `l` 右移。去重三处：固定的 `a` 与上一轮相同则跳过；找到答案后 `l`、`r` 跳过与刚用过的值相同的相邻元素。时间 O(n²)（排序 O(n log n) 被吸收），除输出外额外空间 O(log n)～O(n)（取决于排序实现）。
2. **不排序的哈希方案**：固定两个数 `a`、`b`，用哈希集合查第三个数 `-a-b` 是否在其后出现过；把每个找到的三元组排序后放入集合（或对结果集按规范化形式）去重。时间 O(n²)，空间 O(n)。正确；需要说清如何避免重复使用同一下标、以及结果去重的机制。
3. **暴力三重循环 + 结果去重**：枚举所有下标组合，把三元组排序后放入集合去重。时间 O(n³)，逻辑正确，但在 n = 3000 时明显过慢；核对时承认正确性并指出复杂度问题。

| V2 | 区分“下标不同、值相同是合法三元组”与“结果中不能有重复三元组”：如 `[-1, -1, 2]` 合法，但不能输出两遍 | 必须覆盖 |

含糊表述（如“把重复的去掉”而未说在哪一步、按什么去重）应通过追问澄清，不应直接判错，也不应直接判对。

## 常见错误

- **未排序直接双指针**：双指针的正确性依赖有序性，未排序时移动规则失效。
- **只对固定值去重，找到答案后不对左右指针去重**：在重复值相邻时会输出重复三元组。
- **对输入数组整体去重**（如先转成集合）：把 `[-1, -1, 2]` 这类依赖重复值的合法答案丢掉。
- **跳过条件写错**：固定值去重应与“上一轮已用的值”比较（`i > 0 && nums[i] == nums[i-1]`），与下一轮比较会漏解或越界。
- **右指针起始位置错误**：`l` 应从 `i + 1` 开始，否则可能重复使用下标 `i`。
- 忘记长度小于 3 或空数组的空输出处理。

## 边界情况

- 空数组、长度 1 或 2 → 空列表。
- 全相同元素：`[0,0,0,0]` → 仅 `[[0,0,0]]`；`[1,1,1]` → `[]`。
- 全正或全负 → 空列表。
- 答案依赖重复值：`[-1, -1, 2]` → `[[-1, -1, 2]]`。
- 固定值为 0 且答案含 `[0, 0, 0]` 与含 `[-x, 0, x]` 的混合情形。

## 有区分力的反例

反例 A（区分“找到答案后未对左右指针去重”）：

```
nums = [-2, 0, 0, 2, 2]
正确输出: [[-2, 0, 2]]
错误行为: 固定 -2 后，(l, r) 先后命中 (0, 2) 两次（下标 1,4 与 2,3），
          未去重的实现输出 [[-2, 0, 2], [-2, 0, 2]]。
```

反例 B（区分“对输入去重过度”）：

```
nums = [-1, -1, 2]
正确输出: [[-1, -1, 2]]（两个 -1 来自不同下标，合法）
错误行为: 先把数组去重成 [-1, 2] 再找三元组的实现输出 []。
```

反例 C（区分“未排序直接双指针”）：

```
nums = [-10, 10, 1, 20, 9]（未排序）
正确答案: [[-10, 1, 9]]
未排序直接双指针的行为: 固定 -10 后需要 b + c = 10，l 指向 10、r 指向 9，
  和为 19 > 10 → r 左移到 20，和 30 > 10 → r 左移到 1，和 11 > 10 →
  r 继续左移与 l 相遇，结束；配对 (1, 9) 被错过，最终输出 []。
排序后 [-10, 1, 9, 10, 20]，同一套移动规则可以正确找到 (-10, 1, 9)。
说明: “和偏大移右指针、偏小移左指针”的正确性完全依赖有序性。
```

## 复杂度要求

- 时间：目标 O(n²)。O(n³) 暴力在 n ≤ 3000 时不可接受（应指出会超时）；只说“排序后双指针”但给出 O(n log n) 总复杂度的表述是错误的（双指针内层是 O(n)，外层固定值共 O(n²)）。
- 空间：除输出外，双指针方案 O(log n)～O(n)（排序开销，语言相关）；哈希方案 O(n)。声称整体 O(1) 额外空间时，应追问是否把排序和输出计入。
