## 题意摘要（原创，可独立阅读）

给定一组硬币面值 `coins` 和目标金额 `amount`，求**恰好凑成**该金额所需的**最少硬币枚数**。每种面值的硬币可以使用**任意多枚**（包括零枚）。如果无论如何组合都无法恰好凑出该金额，返回 `-1`。

规则：

- 只关心枚数最少，不关心具体用了哪些面值（但口述时能举例更好）。
- 金额 0 的答案是 0 枚（什么也不用凑）。
- 返回 `-1` 表示无解，它是一个特殊标记，不是枚数。

## 输入

- `coins`：正整数数组，表示可用的硬币面值，互不相同。
- `amount`：非负整数，表示目标金额。

## 输出

- 一个整数：凑成 `amount` 所需的最少硬币枚数；无解时输出 `-1`。

## 约束（本内容采用的规格，供核对使用；与原题的差异以原题链接为准）

- `1 ≤ coins.length ≤ 12`
- `1 ≤ coins[i] ≤ 2^31 - 1`（面值可能远大于金额）
- `0 ≤ amount ≤ 10^4`
- 面值互不相同；不保证包含 1，因此无解是常态而非例外。

## 原创示例

示例 1：

```
输入: coins = [1, 3, 4], amount = 6
输出: 2
解释: 6 = 3 + 3，共 2 枚。注意贪心地先取最大面值会得到 4 + 1 + 1 共 3 枚，
      不是最优。
```

示例 2：

```
输入: coins = [2], amount = 3
输出: -1
解释: 只有面值 2，任何枚数之和都是偶数，凑不出 3。
```

示例 3：

```
输入: coins = [5], amount = 0
输出: 0
解释: 金额为 0，不需要任何硬币。
```

## 可接受方案（不止一种，不作为唯一正确答案）

1. **自底向上动态规划（目标解法）**：设 `dp[x]` = 凑出金额 `x` 的最少枚数。`dp[0] = 0`；对每个 `x` 从 1 到 `amount`，`dp[x] = min(dp[x - c] + 1)`，其中 `c` 遍历所有满足 `c ≤ x` 且 `dp[x - c]` 可达的面值。不可达状态用一个大于任何可能答案的哨兵（如 `amount + 1` 或 ∞）表示；最终 `dp[amount]` 仍是哨兵则返回 `-1`。时间 O(amount × k)，空间 O(amount)，k 为面值种数。
2. **自顶向下记忆化递归**：`f(x) = 1 + min(f(x - c))`，`f(0) = 0`，负数金额与已判无解的金额直接返回不可达；用备忘录避免重复子问题。复杂度同上。与方案 1 是同一递推的两种实现方向，均应认可。
3. **BFS 按层扩展**：把金额看作节点，从 `amount` 出发每次减去一种面值，按层（枚数）扩展，第一次到达 0 的层数即答案；访问过的金额不再入队。时间 O(amount × k)，空间 O(amount)。正确，且“第一次到达即最少”依赖 BFS 按层性质，用户应能说明。
4. **朴素递归（无记忆化）**：逻辑正确但子问题指数级重复，在 `amount ≤ 10^4` 下不可接受；核对时承认思路方向正确，并追问/指出需要记忆化或改递推。

注意：**贪心（每次尽量取最大面值）不是可接受方案**，它并不总得到最少枚数，甚至可能误判无解（见反例）。用户若主张贪心，应给出反例引导，而不是直接接受。

## 常见错误

- **贪心取最大面值**：并非最优（反例 A），甚至可能把有解判成无解（反例 B）。
- **哨兵污染**：不可达状态初始化为 0，导致 `min` 永远取 0；或哨兵取 ∞ 后未在最后判断，直接输出 ∞。
- **漏掉 `dp[0] = 0`** 基础情形，或把 `amount = 0` 输出成 -1。
- **无记忆化的指数级递归**：方向对但会超时，且用户常意识不到重复子问题规模。
- **把 -1 参与后续转移**：无解状态被当作“枚数 -1”继续 `+1` 传播。
- **面值大于金额时未跳过**：数组下标越界或引入负金额状态。

## 边界情况

- `amount = 0` → 0（不是 -1）。
- 无任何组合可达（`coins = [2]`, `amount = 3`）→ -1。
- 所有面值都大于 `amount`（且 `amount > 0`）→ -1。
- `coins = [1]` → 答案就是 `amount`。
- 面值极大（接近 2^31-1）：只影响比较与跳过逻辑，不应导致溢出错误的设计。
- 最优解需要大量重复同一面值（如 `coins = [3, 5]`, `amount = 15` → 3 枚 5，也可 5 枚 3，最少 3 枚）。

## 有区分力的反例

反例 A（贪心非最优）：

```
coins = [1, 3, 4], amount = 6
贪心: 先取 4，剩 2 → 1 + 1，共 3 枚 (4+1+1)
最优: 3 + 3，共 2 枚
```

反例 B（贪心误判无解）：

```
coins = [5, 3], amount = 6
贪心: 先取 5，剩 1，无面值可凑 → 误报 -1
实际: 3 + 3 = 6，答案 2
```

反例 C（区分“哨兵/基础情形处理错误”）：

```
coins = [2], amount = 3
若把不可达初始化为 0 而不是哨兵: dp[3] 会取到 min(dp[1] + 1) = 0 + 1 = 1，
错误输出 1 枚；正确输出 -1。
```

## 复杂度要求

- 时间：O(amount × k)，k = 面值种数（≤ 12），amount ≤ 10^4，完全可行。朴素无记忆化递归是指数级，不可接受，应指出并引导加备忘录。
- 空间：O(amount)（dp 数组/备忘录/BFS 访问集合）。记忆化递归另需 O(amount) 递归栈深度，说出这点是加分而非必须。
