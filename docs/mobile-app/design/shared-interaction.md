# 页面、状态与交互规范：雾绿延续

颜色与组件外观已冻结为[雾绿视觉 tokens](visual-spec.md)。本页规定信息架构、响应式与行为；前端负责人可依此实现，但不得重新解释任务优先级或状态语义。

## 画布、尺寸与响应式

| 项 | 规则 |
| --- | --- |
| 基准视口 | 390 × 844 CSS px；导出为 1170 × 2532 px @3x。 |
| 内容边距 | 20 px（375/390）；428 宽保持 24 px，并限制阅读宽度，不按比例放大字。 |
| 安全区 | 顶部 `max(16px, env(safe-area-inset-top))`；底部导航/固定操作区使用 `max(12px, env(safe-area-inset-bottom))`。 |
| 可触目标 | 最小 44 × 44 px；主按钮 52–56 px 高，不能只依赖图标。 |
| 圆角 | 输入/轻卡片 12–14 px；主按钮 14 px；避免大药丸和每层都有阴影。 |
| 分隔 | 1 CSS px；使用留白和线分组，最多一层表面容器。 |
| 动态字体 | 支持 iOS 较大字号：正文和题目可增大，页面纵向滚动；不截断题目和反馈。 |
| 375 宽退化 | 辅助元信息换行/下移；主按钮全宽；底部导航文字保留；不缩小 16 px 正文。 |

## 字级与间距

| Token | CSS 值 | 用处 |
| --- | --- | --- |
| `body` | 17 px / 28 px | 题意、回答、反馈正文。 |
| `body-small` | 14 px / 21 px | 元信息；非关键内容。 |
| `label` | 14 px / 20 px, 600 | 分组、状态和输入标签。 |
| `title` | 26 px / 35 px, 600 | 题目与结论。 |
| `display` | 30 px / 40 px, 600 | 今日一句话；每页最多一个。 |
| `space-1…6` | 4 / 8 / 12 / 16 / 24 / 32 px | 只使用这些间距，区块之间通常 24 或 32 px。 |

## 五个关键屏幕

### 今日

- 首屏顺序固定：日期与短问候 → “继续上次”（若存在）→ 主按钮 → 练八股 / 讲算法 → 待复习。
- 不把统计、长说明、设置或二级导航放在开始入口之前。统计只能出现在上述任务之后。
- 底部四入口为“今日 / 八股 / 算法 / 我的”；复习从今日和科目入口进入。专注作答页隐藏底部导航。

### 八股作答

- 顶部只保留返回与“八股 · 1 / 3”进度；问题优先于类别、分数和设置。
- 一个语音兼容的文本输入框；先写/说，再点“核对回答”。参考答案与提示是次级文字操作，默认收起。
- 默认反馈不放总分或四张分数卡；已说对和最值得补充各不超过 1–3 条。

### 算法作答

- 首层依次为：题名、可独立阅读的题意/示例、一个“讲讲你的思路”输入框、主按钮“帮我核对”。
- 代码、复杂度、边界、提示都放在“可选展开”之后；没有代码不能形成减分暗示。
- 用户按下核对时，先保存草稿/回答，界面显示“已安全保存这次回答”。修改回答后应标记旧反馈已过期，不能复用。

### 核对反馈

- 首屏固定三层：一句结论（如“方向成立”）→ 已说对 → 最值得补充。每层必须引用或对应用户实际说过的内容。
- 主行动随上下文为“补充后再核对”；次行动“下一题”。详细参考思路、复杂度、边界和来源折叠，避免直接倒出完整解法。
- 用文案与结构表达“思路核对”，不出现“AC”“通过测试”“AI 助手”类在线判题暗示。

### 复习列表

- 按到期顺序列出；每项只有到期时间、题目和一个下一步动作。无掌握度仪表盘。
- 看参考答案只记录为“已查看”，不自动标为掌握；“稍后复习”沿用现有调度规则。

## 组件草案

| 组件 | 结构 / 状态 |
| --- | --- |
| `PrimaryAction` | 满宽、52–56 px 高；`accent` 实底、白字；默认、按下、禁用、加载。加载仍显示动作含义，如“正在核对”。 |
| `TextAction` | `accent` 文字 + 右箭头；最少 44 px 触区；不作为唯一的关键提交动作。 |
| `AnswerField` | `surface` + `rule`、标签、可增长多行文本、草稿状态；聚焦时 2 px `accent` 边，不用单靠颜色。 |
| `FeedbackBlock` | 结论 / 已说对 / 待补充 / 详情；“已说对”用 `accent-subtle`，结论必须有文字。 |
| `ReviewRow` | 到期、题名、单一行动；全行可点，`rule` 分隔线而非堆叠卡片。 |
| `FocusHeader` | 返回、进度、可选保存状态；没有全局 tab；`rule` 底线。 |

## 必要状态与转场

### 键盘展开

- 输入框获得焦点后，页面可滚动，使当前光标和题目上下文仍可见。
- 提交按钮定位在键盘上沿以上，随 `visualViewport`/键盘高度移动；底部导航在专注页隐藏，避免“导航 + 键盘 + 固定栏”三层重叠。
- 用户用 iPhone 键盘听写产生的正常文字，与手打同等处理；不承诺应用内录音。

### 核对中

- 点击后立刻禁用重复提交，保存状态先可见，再用非阻塞转圈和“正在对照题目条件与思路要点”说明。
- 允许离开：草稿已保存，回来继续显示状态/结果。按钮不能只显示无意义 spinner。

### 失败重试

- 文案明确“这次回答已保存”“不是答案有问题”；提供“重新核对”和“返回题目”。
- 重试复用同一回答版本，不能重复写入一次练习记录。若用户编辑，再产生新版本并让旧反馈过期。
- 网络、服务超时、无效响应统一为可理解的失败面，技术细节只在可展开“详情”。

### 无内容

- 复习为空时给出完成感与两条自然去向（练 3 道八股 / 讲一道算法），不显示空表格、零统计或插画占满屏。

### 动效和可访问性

- 按压、展开、切题仅 150–220 ms；系统“减少动态效果”下即时切换。
- 所有状态有文字和形状/结构，非仅颜色；前景文字和控件满足可读对比。
- 键盘焦点顺序遵循视觉顺序；返回、提交、重试、下一题均有可读标签。

## B 的实现禁区

- 不把今日改回统计优先，不把八股开局改回配置表单，也不让算法作答首层要求代码/复杂度/自评。
- 不引入渐变、玻璃、深阴影、大圆角、彩色统计卡、AI 星光或后台仪表盘语言。
- 不擅自改动本规范的颜色层级；需要深色主题或品牌扩展时先回到视觉负责人。
