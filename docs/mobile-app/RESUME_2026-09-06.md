## 关键依赖和验收点

1. A 修正后的图稿才是视觉验收基准。B 可立即做结构、组件、状态和 fixtures，不能把旧三倍导出图的像素直接当 CSS 尺寸。至少检查 375、390、428 宽度，不凭不精确的手机名称锁定一种屏幕。
2. C 先统一协议小修，再由 B/D 按同版对接。网络返回丢失可能已经保存，需用同一 `client_answer_id` 恢复；同 ID 不同内容、重试重复写进度、修订与旧反馈错配都要有明确行为。可采用“一次点击先保存再核对”，无需任务队列。
3. D 不再等待不存在的协议。先交三题给 C/E，再继续扩充。题意和样例原创整理，确实读过来源才写核实记录；不能为数量将不确定内容标 ready。上下文版本由 C 导入器管理。
4. 用户输入未确认保存时不得显示服务端已保存。模型失败不是答案错误；信息不足时追问，允许多种正确解法，不能要求用户复述唯一标准答案。
5. E 在自己的集成分支合入已交付提交后，再验收“读题→输入→保存→核对→失败重试→历史/复习”。mock、浏览器仿真、真实模型和实体设备是不同证据，记录中必须说清。
