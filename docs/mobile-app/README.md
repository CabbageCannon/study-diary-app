## 目标与范围

为客户自己使用的 iPhone 做一个可以随时打开的学习 App：碎片时间练八股，通过讲述算法思路获得具体核对反馈，并能接着上次继续。视觉应简洁、优雅、舒服、有 ins 感。

已确认：个人自用；主要设备为 iPhone；不扩展多用户、复杂权限、高并发或商业化系统。保留模型密钥在服务端、个人数据不进入公开 GitHub、可恢复备份这些基础操作即可。

建议默认：保留现有 React + TypeScript + Vite / FastAPI 技术栈和 SQLite。第一阶段交付可添加到 iPhone 主屏幕的 PWA；这需要一个手机可访问的 HTTPS 服务，不能把电脑 localhost 当成随时可用的地址。后端要在客户希望使用的时段可访问。若以后明确需要 TestFlight 或 App Store 分发，再评估 Capacitor 打包；本阶段不承诺商店上架或原生应用安装包。

输入默认采用文字 + iPhone 键盘语音。客户尚未明确要求应用内录音为首发必需，独立录音、转写、重录暂列后续增强。LLM 核对需要联网；第一阶段离线保障本机草稿，不承诺完整离线题库或离线评分。

## 手机信息结构

建议四个底部入口：**今日 / 八股 / 算法 / 我的**。复习从今日和各科入口进入；日记、历史和设置收进“我的”，保留已有功能。桌宠和题库审核不占手机学习主入口。已有 `/interview/review` 是题库审核，不能误当作个人八股复习页面。

练习过程中进入专注页面：轻量返回、题目进度、题目正文、回答区域、一个主要操作。回答时隐藏主导航，退出回到进入前的位置。避免底部导航、系统键盘、固定提交栏三层叠在一起。

### 今日

一行日期和简短问候；有未完成记录时优先显示“继续上次”；清楚提供“练几道八股”和“讲一道算法”。到期复习是一行次级入口；学习统计放在下方。正常已加载状态，从首页到可回答题目不超过两次点击。

### 八股：先回忆，再核对

默认继续上次，或用最近设置开始短题集，推荐默认 3 题。分类与难度通过轻量筛选打开，不再挡在首次开始之前。

顺序：看问题 → 自己回答 → 点“核对回答” → 看到一句结论、已说对的要点和最值得补充的内容 → “再说一次”或“下一题”。参考答案默认收起，主动查看后记录为看过参考，避免把阅读直接等同于掌握。

默认反馈不展示四张分数卡和长报告。详细评分、来源、完整参考答案保留在展开区域。支持“稍后复习”；复用已有复习安排，不新建另一套冲突的掌握度系统。

### 算法：以讲清思路为完成方式

顺序：阅读题意与示例 → 输入或口述自己的方案 → 点“帮我核对” → 看具体问题 → 补充回答 → 再次核对或下一题。

回答只要求一个思路输入框。复杂度、边界条件可以一起讲，也可以由核对后的一条追问引导补充；代码、语言、计时、卡点、长篇复盘都作为可选展开内容。用户不需要先给自己选择“已解决”，也不需要理解“先保存记录再请求复盘”的内部步骤。

保存与评估在用户动作上合并，在数据处理上分开：先可靠保存当前回答，评估失败仍能恢复；重试评估复用同一次回答，不重复产生记录。修改思路后生成可追溯的新版本或新尝试；旧反馈不能冒充新回答的反馈。具体接口由后端负责人设计。

反馈默认只显示：

1. 一句结论：思路成立 / 还差一步 / 存在关键错误 / 信息不足。
2. 最值得注意的一到三点，引用用户实际说过的内容。
3. 必要时给一个反例或一个追问。

详细区包含时间与空间复杂度、遗漏边界和参考思路。不默认倾倒完整答案。对不同但有效的解法应认可；没有代码不能成为扣分理由。页面文案使用“思路核对”，不能显示为在线判题“AC”。

示例：两数之和，用户说“遍历，用哈希表存已经见过的数”。合适反馈：“方向成立。还需要说明先查补数再存当前值，这样不会把同一个位置使用两次。时间 O(n)，额外空间 O(n)。”若用户实际上没讲查询顺序，应标为待补充，不擅自断言其实现一定错误。

## 题目与核对依据

手机用户必须能在 App 内知道题目要求。首批建议覆盖现有八股和 10–15 道具有完整核对依据的算法题；这是建议验收规模，不是假定已有内容全部合格。

每道启用思路核对的算法题至少具有：独立编写的题意摘要、明确输入输出、约束、原创小示例、可接受解法要点、常见错误、边界条件、来源以及内容版本。保留原题链接供核实。公开仓库不批量复制外站完整题面或题解。

后端向 LLM 提供该题版本的上下文和用户回答，不依赖标题猜题。题目上下文不全、回答含糊或需要未提供条件时，应返回“信息不足”并追问；不编造约束和测试通过结果。LLM 输出不是绝对正确证明，验收用固定样例检查有用性和错误接受情况。

内容负责人维护原始数据，后端负责人维护 schema、导入器和 API，避免两人同时修改公共模型。

## 视觉方向：安静的随身学习册

ins 感来自色彩、留白和排版：暖白或非常浅的灰绿背景，墨色正文，一种低饱和植物绿作为强调；可比较奶油纸张方向与当前浅绿方向。不要把 ins 感解释成照片瀑布流。

- 一屏一个主要任务；题目本身具有视觉优先级。
- 中文正文建议 16–18px、行高约 1.65；题目约 24–28px，中等字重。大标题不得挤走开始练习按钮。
- 页边距约 20–24px，主要触控目标至少 44px，适配 390 和 428 CSS px 宽度，并检查 375 宽度退化。尺寸是验收视口，不推断具体手机型号。
- 薄分隔线和留白为主，少量柔和圆角；避免层层套卡片、大阴影、彩色统计块、玻璃效果、闪光图标和“AI 助手”装饰。
- 正文优先 iPhone 系统中文字体；衬线字只可作为少量日期或章节装饰，不能牺牲阅读。
- 动效只帮助识别切题、展开和按下状态，约 150–220ms，并支持减少动态效果。
- 前景文字对比度不能为了淡雅而降低；主要反馈不能只用颜色表达。

先让设计负责人交付：首页、八股作答、算法作答、核对反馈、复习列表五个关键页面和必要异常状态。先比较两种克制方向，再统一一套视觉规范交给前端；应用的界面实现必须服从同一套规范。

## 阶段与完成标准

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| M0 基线 | 当前 demo 的可复现提交与基线说明 | 未提交改动逐项归属清楚，私有文件排除，相关检查通过，发布统一 commit SHA |
| M1 体验与协议 | 关键屏幕、设计规范、核对 API 协议与题目样例 | 客户选择视觉方向；前后端按同一请求/响应样例工作 |
| M2 学习闭环 | 八股、算法思路核对、继续训练、复习 | 真数据能完成一题；失败可重试；旧记录兼容 |
| M3 手机交付 | HTTPS PWA、安装引导、真机验收报告 | 手机离开电脑局域网后仍可用；键盘不挡操作；刷新恢复草稿；更新不强制中断 |

视觉探索、内容准备和接口设计可以先行；功能实现以 M0 基线和 M1 协议为前提。先完成一条端到端纵向流程，再扩大页面和题目覆盖。

个人使用不要求商业级平台。验收优先顺序：回答不丢 → 核对有依据 → 手机操作顺畅 → 视觉一致 → 安装和随时访问。暂不做排行榜、社交、商城、复杂仪表盘、在线代码沙箱、桌宠扩展、独立录音基础设施。
